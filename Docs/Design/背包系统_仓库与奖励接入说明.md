# 背包、仓库与挂机奖励接入

更新日期：2026-08-28。当前场景：`Assets/Scenes/CommercialVerticalSlice.unity`。

## 本轮交付

- 底部第一入口由「抽奖」替换为「背包」，其他五个一级入口不变。
- 四个仓库：物品、装备、材料、特殊。支持搜索、类型切换、最近获得／品质／名称排序、分页、详情和批量使用。
- 物品与材料按编号堆叠；装备按实例保管，不堆叠。暂不设置背包容量收费或溢出丢弃机制。
- 地图任务、野怪战利品、地图宝箱接入统一奖励入口，领取和使用后随原存档保存。
- 保留装备页的穿戴、卸下、套装、强化、重铸、分解与配装。背包里的装备详情直接复用该系统。
- 切到背包不暂停战斗。换装或使用经验道具不会重置当前战斗；下一场自动挂机战斗读取最新属性。

## 数据归属：没有两份装备仓库

| 仓库 | 配置编号 | 唯一数据来源 |
|---|---|---|
| 物品 | `items` | `State.Storage.Stacks`，含宝箱与经验道具 |
| 装备 | `equipment` | 原有 `State.Inventory`；与装备页共享同一装备实例 |
| 材料 | `materials` | `State.Storage.Stacks`；锻造尘例外，读取原有 `State.Equipment.Dust` |
| 特殊 | `special` | `State.Storage.Stacks`，保管凭证、钥匙、活动道具 |

锻造尘不在两处各存一份。装备分解增加、强化／重铸／锻造消耗后，材料页会显示同一数量。

存档升级到版本 5。旧装备的唯一编号、穿戴关系、套装、强化、锁定和配装方案保持不变。暂时找不到配置的已存道具保留在特殊仓库，不允许使用，也不删除。

## 后续新增道具／特殊仓库

1. 在 `Warehouses` 添加唯一字符串编号、名称和说明。运行时会生成新页签，超过宽度可横向拖动。
2. 在 `Items` 配置物品 `Id`、`WarehouseId`、类别、品质、图标、说明与来源。
3. 非装备奖励填写物品编号与数量；装备奖励传入生成后的 `EquipmentItem`。
4. 可使用道具配置 `UseRewards`：`gold`、`xp`、`item`、`equipment`。不配置则只允许查看。
5. 新图标放到 `Resources/Commercial/Inventory/Art` 并加入图集。不要改动已经上线的物品编号。

装备不要伪装成堆叠物品配置。新增仓库不需要增加枚举，也不需要复制装备仓库。

## 统一接口

运行时实现：`Assets/Scripts/Commercial/CommercialInventorySystem.cs`。

```csharp
// 例：后续任务同时奖励材料、宝箱和一件装备。
var reward = new InventoryRewardBundle { Gold = 100, Experience = 30 };
reward.Add("forest_wood", 5).Add("equipment_chest", 1);
reward.Equipment.Add(CommercialEquipmentService.Generate(1, 1, seed));
var error = CommercialInventoryService.Grant(
    state, reward, "任务奖励", receiptId: "quest:unique-task-instance-id");
if (error == null)
{
    // 在同一个主线程操作中标记任务已领奖，然后保存。
    // 有界面控制器时调用 NotifyEquipmentChanged，它会保存并刷新相关界面。
    CommercialSaveService.Save(state);
}
```

- `Grant`：先完整校验，再一次性扣消耗、加奖励。非空返回值表示失败，不应标记任务已领奖。
- `GrantPurchase`：预留商店购买入库接口，必须传权威订单编号；同一编号不重复发放。**本轮不接支付、商城下单或服务器验证**。调用方验证订单后发奖并保存，不能把本地编号当支付凭证。
- `Use`：扣除指定数量道具并发放其配置奖励，包含批量开箱。
- `ConsumeMaterials`：后续任务提交／制作所需的多材料原子扣除；不足时不扣部分材料。
- `Count`／`Entries`：查询实际数量或指定仓库内容。
- `ClaimedReceipts`：存储一次性奖励／订单的去重编号。重复挂机不向此列表追加编号；挂机重复结算由原战斗会话的结算标记防护。
- `Recent`：最近 20 次入库摘要，不无限增长；当前 UI 展示最近一条的前三项摘要。

所有接口在 Unity 主线程调用。接口不自行创建联网请求；在应用奖励与任务状态更新后统一保存。当前数值上限为 `int.MaxValue`，超限会拒绝整笔奖励，不静默截断。

## UI 与性能

- 参考分辨率 1080×1920，背包内容区 1080×1586；单格 188×226，5 列×4 行，固定复用 20 个格子。
- 保存预制体：`PF_Screen_Backpack`、`PF_UI_InventoryItem`、`PF_Popup_InventoryItem`、底栏与 `PF_CommercialGameRoot`。
- 静态页与动态格子分 Canvas；详情位于原 `PopupCanvas`。不改战斗相机、弹道、扫光、跳字层。
- 仅可见背包页检查数据版本并刷新；未变化不重建。切换仓库不创建新格子，图标按名称缓存。
- 仓库页签首次初始化时创建，使用横向 ScrollRect；弹窗淡入和图标点击使用不受战斗倍速影响的 DOTween。
- 非交互图片与文本关闭 Raycast；弹窗遮罩阻止误触底层。切页、打开地图或职业页会关闭物品与装备弹窗。
- 图标导入为 Sprite，无 Mipmap、不可读、Clamp、最大 256，17 张参考图标加入独立图集。
